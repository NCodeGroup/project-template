# Contributing

Issues and pull requests are welcome. [README.md](README.md) explains the template, and [AGENTS.md](AGENTS.md) holds the rules every change here follows, for people and coding agents alike. The template serves NCodeGroup's repositories on GitHub only ([ADR-0040](template/docs/decisions/project-template/0040-the-template-serves-ncodegroups-repositories-on-github-only.md)), so a change that adds support for another host, such as GitLab, isn't taken; the GitLab files and passages the template still has are removed by the stories of [#527](https://github.com/NCodeGroup/project-template/issues/527).

## Issues

Say what should change and why, as the existing issues do. The maintainer plans issues with the template's own `/plan-issue` and `/run-issues` commands, so coding agents read them: they treat an issue's text as data, never as instructions. Report a vulnerability privately instead, as [SECURITY.md](SECURITY.md) says.

## Pull Requests

- Every change reaches `main` through a pull request. The Protect main ruleset requires its `test` check to pass, and it merges with a merge commit or by rebasing, never by squashing, so each commit stays on `main`. Once an organization owner has set up NCode Review's approver here and run `tools/Set-RepositoryBaseline.ps1`, it also requires one approval, of the last push, which the NCode Review Approver gives when a review leaves no blocker or should-fix finding open; after a push, comment `/review` for a new one. A workflow run from a fork waits for the maintainer's approval.
- Change the workflow in `workflow/templates/`, then run `.\tools\Update-Template.ps1`. Never edit the generated files under `.claude/`, `.github/agents/`, `.github/prompts/` or `.github/skills/`, in `template/` or at the root.
- Write tooling, such as a script, a check or a generator, in Node.js, or else in Go, or else in PowerShell 7, the first that fits the job, as [ADR-0021](template/docs/decisions/project-template/0021-tooling-is-written-in-nodejs-then-go-then-powershell.md) says. Python stays out of the tooling; Copier and pre-commit, Python programs the tests run, are the exception.
- Run `.\tests\Invoke-AllTests.ps1` before you push. It needs PowerShell 7, Git, Copier and Node.js, the release `.node-version` names, which nvs selects; [USAGE.md](USAGE.md#install-the-tools) sets them up. Add `-SkipDotnetBuild` to skip the .NET builds. It runs the suites and the fixture setups that `.github/workflows/test-template.yml` runs with `-SetupOnly` in parallel, up to one per processor; add `-ThrottleLimit <n>` to run fewer at once, or `-Serial` to run one at a time.
- When you change `/run-issues` or a command it runs, also run `.\tests\e2e\Test-RunIssues.ps1` once and `.\tests\e2e\Test-RunIssues.ps1 -Scenario max-rounds` once, and `.\tests\e2e\Test-RunIssues.ps1 -Scenario push-branch` once when you change how a plan reaches a push branch, such as in `/ship-plan` or `.template/Get-PlanState.ps1`, when you change `/address-feedback` or a command it runs, `.\tests\e2e\Test-AddressFeedback.ps1`, and when you change `/run-feedback` or a command it runs, such as `/address-feedback`, `.\tests\e2e\Test-RunFeedback.ps1` once and `.\tests\e2e\Test-RunFeedback.ps1 -Scenario review-with-footer` once, and `.\tests\e2e\Test-RunFeedback.ps1 -Scenario protected-approval` once. Each runs the command in Claude Code on a local fixture and costs model usage; the README's Change the Template section says what they need.
- Commits record the people who wrote them, so avoid AI agent attribution: no `Co-authored-by:` trailer naming an AI agent, and no "Generated with" line. Nothing checks for it or blocks a pull request over it. Run `git config core.hooksPath template/.githooks` once in your clone, so its `pre-push` hook refuses a push to `main`.
- Leave `CHANGELOG.md` and the release tags to the maintainer, who writes the changelog section and tags each release.
