The `board` line of `AGENTS.md`'s `## Landing` section, which the state script prints as `board=<owner>/<number>` on its `landing` line, names the project's board: a GitHub Project of that organization whose Status field has the columns Backlog, Ready, In progress, In review and Done, as ADR-0042 in `docs/decisions/project-template/` records. With `board=none`, the default, move nothing; with `board=invalid`, move nothing and say that the Landing section's `board` line takes `none` or `<owner>/<number>`, such as `NCodeGroup/7`. To move an issue to a column, read the board's fields once per run, `gh api "orgs/<owner>/projectsV2/<number>/fields?per_page=100&page=1"`, one page, which holds the Status field because a project has far fewer than 100 fields, and take the field whose `name` is `Status`: its `id`, and the `id` of its option whose `name` is the column. Add the issue to the board with `gh api orgs/<owner>/projectsV2/<number>/items -f type=Issue -f owner=<repository owner> -f repo=<repository name> -F number=<issue number>`, which answers with the issue's item, also when the issue is on the board already, and take the item's `id`; `<repository owner>` and `<repository name>` are the two parts of what `gh api repos/{owner}/{repo} --jq .full_name` prints. Then write `{"fields":[{"id":<field id>,"value":"<option id>"}]}` to a temporary file outside the repository with your file-writing tool, and set the item's Status with `gh api -X PATCH orgs/<owner>/projectsV2/<number>/items/<item id> --input <file>`. A board move never stops the command: when one fails, as it does without the `gh` token's `project` scope or in a session whose network allows only repository paths, say which issue wasn't moved and why, and go on.
