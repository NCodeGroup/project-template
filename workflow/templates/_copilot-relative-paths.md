`Set-Location` moves PowerShell's location, not the process's current folder, which stays where the session started, such as the main checkout. A .NET method, such as `[IO.File]::ReadAllText`, `[IO.File]::WriteAllText`, `[IO.Directory]::GetFiles` or `[IO.Path]::GetFullPath`, resolves a relative path against the process's folder, so a script that passes it one reads or writes the main checkout instead. Never pass a relative path to a .NET method: use PowerShell's own commands, such as `Get-Content -LiteralPath`, `Set-Content -LiteralPath` and `Get-ChildItem`, or make the path absolute first, with `Join-Path (Get-Location) <path>` or `$ExecutionContext.SessionState.Path.GetUnresolvedProviderPathFromPSPath('<path>')`.
