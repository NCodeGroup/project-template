## Plan in a worktree of its own

Each plan lives in its own git worktree, so several Copilot sessions, or Copilot and Claude Code sessions, can plan and execute different plans in one clone at once, and the main checkout stays as it is. Executing, re-planning and reviewing this plan later happen in the same worktree. When the task names the plan's folder and says this section is done, as `/run-issues` and `/address-feedback` do, that folder is `<plan folder>`: skip items 1 to 3. Otherwise set the worktree up before you read any code, so your research matches the code the executor will change:

1. Run `git rev-parse --show-toplevel`. `<plan folder>` is the path it prints until item 3 changes it.
   - When the environment variable `GITHUB_ACTIONS` is `true`, this session is Copilot's cloud agent, whose runner keeps only the commits pushed from its clone: plan in this checkout, on the branch it is on, create no worktree, and go on with item 4.
   - When the path contains `/.claude/worktrees/`, or `git rev-parse --path-format=absolute --git-dir` and `git rev-parse --path-format=absolute --git-common-dir` print different paths, this session is already in a worktree: use it, unless its `PLAN.md` has a step not yet marked `[x]`. In that case stop, because the worktree holds a plan in progress, and tell me to start the new plan from a new session in the main checkout. Otherwise settle the clone's Git settings as item 3 says, create no worktree, and go on with item 4.
2. Otherwise, if `git check-ignore -q .claude/worktrees/` exits non-zero, append the line `.claude/worktrees/` to `info/exclude` in the folder that `git rev-parse --path-format=absolute --git-common-dir` prints, so the main checkout doesn't list worktrees as untracked files.
3. Then, still in the main checkout, which you only read, settle the clone's Git settings before the worktree exists, because the worktree shares the clone's Git config. {{PROMPT:_git-hooks}} {{PROMPT:_push-branch-session}} Then create the worktree:
   - Name it with two to four lowercase words from the request, joined by hyphens, such as `csv-export`, that are not already a folder under `.claude/worktrees/` and not already a branch `worktree-<name>`.
   - Run `git fetch origin`.
   - Choose the base: the branch that `git symbolic-ref --short refs/remotes/origin/HEAD` prints, such as `origin/main`. If that command fails, run `git remote set-head origin --auto` and run it once more. In a clone without `origin`, the base is `HEAD`.
   - Run `git worktree add --no-track -b worktree-<name> .claude/worktrees/<name> <base>`, which never switches the main checkout's branch.
   - `<plan folder>` is now the new worktree's absolute path.
4. A worktree is a fresh checkout, without ignored files such as installed dependencies. If the build or test command needs a setup step first, such as `npm ci`, run it in the worktree and list it under Context for the executor.

From here on, `<plan folder>` is the repository root: read, write and run commands only there, never in the main checkout. A Copilot session can't change the folder its shell starts in, so start every command with `Set-Location -LiteralPath '<plan folder>';`, give file tools absolute paths under `<plan folder>`, and search with `git -C '<plan folder>' grep` or by path, because a workspace search skips the ignored `.claude/worktrees/`. When you delegate to a subagent, give it `<plan folder>` and these rules, and tell it to work only there.

`PLAN.md` stays untracked in the worktree and is never committed or pushed. After writing it, run `git commit --allow-empty -m "Plan: <the plan's title>"` in `<plan folder>`. End your reply with the worktree's name, folder and branch, and how to continue: `/orchestrate-plan <name>` from a session in the main checkout, or `/orchestrate-plan` from a session opened in `<plan folder>`, such as `copilot` started there or a VS Code window on that folder.
