Issue types, parents, sub-issues and "blocked by" links are read and written through `gh api` with REST paths, in every session, because their `gh issue` forms need GitHub's GraphQL API, which a Claude Code cloud session refuses. `gh api repos/{owner}/{repo}/issues/<number>` gives an issue's `id`, `number`, `title`, `body`, `state`, `labels` and `html_url`, its type as `type.name` (`Epic`, `Feature`, `Bug` or `Task`, or `null` without one), its parent as `parent_issue_url`, which ends in `/issues/<parent number>`, or `null`, `sub_issues_summary` with `total` and `completed`, and `issue_dependencies_summary` with `total_blocked_by`; its comments are `gh api "repos/{owner}/{repo}/issues/<number>/comments?per_page=100&page=<n>"`. `gh api "repos/{owner}/{repo}/issues/<number>/sub_issues?per_page=100&page=<n>"` lists its sub-issues, in their order, and `gh api "repos/{owner}/{repo}/issues/<number>/dependencies/blocked_by?per_page=100&page=<n>"` the issues it is blocked by; each entry has `id`, `number`, `title`, `state` and `html_url`, whose path names its repository. Read one page at a time, from 1 until a page holds fewer than 100 entries, never with `--paginate`. Create an issue with its type with `gh api repos/{owner}/{repo}/issues -F title=@<title file> -F body=@<file> -f type=<type>`, where the title file holds the title with no line break after it, and whose answer gives its `id`, `number` and `html_url`; set an existing issue's type with `gh api -X PATCH repos/{owner}/{repo}/issues/<number> -f type=<type>`. Link a sub-issue with `gh api repos/{owner}/{repo}/issues/<parent number>/sub_issues -F sub_issue_id=<id>`, and a blocker with `gh api repos/{owner}/{repo}/issues/<number>/dependencies/blocked_by -F issue_id=<id>`, where `<id>` is the sub-issue's or the blocker's `id`, never its number. Edit an issue's body through JSON and a file: read it as `(gh api repos/{owner}/{repo}/issues/<number> | ConvertFrom-Json).body`, change the text, write it to a temporary file outside the repository with your file-writing tool, and send it with `gh api -X PATCH repos/{owner}/{repo}/issues/<number> -F body=@<file>`; never pass a body through a shell variable's lines or the command line, which loses its line breaks. A read of the issue itself, `gh api repos/{owner}/{repo}/issues/<number>`, that fails, with a non-zero exit, an API error or a refused route, answers nothing and is never read as "no type, no parent": only an answer whose `type` is `null` is an issue without a type, and only one whose `parent_issue_url` is `null` an issue without a parent. Name the issue and the call that failed, and do what these instructions say for that read; where they say nothing, stop. A read of an issue's sub-issues, or of the issues it is blocked by, that fails answers nothing too, and is never read as an empty list, which would let a blocked story through or file a story again: name the issue and the call that failed, and do what these instructions say for that read; where they say nothing, stop.
