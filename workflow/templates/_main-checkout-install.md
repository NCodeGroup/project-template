A worktree lies inside the main checkout, so a tool that looks in the folders above a file for its config can reach the main checkout's, such as Vite looking for the `tsconfig.json` that covers a file, and resolves the packages that config names, such as its `extends`, from the main checkout's `node_modules`, never the worktree's: without them the build fails, such as with `Tsconfig not found astro/tsconfigs/strict`. So when the setup step installs Node.js packages, such as `npm ci`, `pnpm install`, `yarn install` or `bun install`, and the main checkout, the folder that the first `worktree` line of `git worktree list --porcelain` names, is not the worktree and has a `package.json` but no `node_modules` folder, run the same command there too, with the main checkout as its working folder. It adds only ignored files and changes nothing Git tracks; never touch a `node_modules` folder the main checkout already has. When the install fails, go on, and say so in your reply with its error. In a plan, say under Context for the executor that the main checkout's packages were installed, and why.
