Post each comment and reply from a file of its own, written with your file-writing tool before the command runs: never build a body in a shell variable or a loop over a table, and never pass one as an argument, such as `-f body=...`, `-F body=$text` or `--body ...`, because the shell expands it first, and PowerShell turns an expression such as `$replies[$key]` on a hashtable into the hashtable's type name. Keep the file until its post is checked. Right after each post, read it back by the id its answer gives: on GitHub, a thread reply's `id`, or the number after `#discussion_r` in its URL, with `gh api repos/{owner}/{repo}/pulls/comments/<id> --jq .body`, and a top-level comment's number after `#issuecomment-`, with `gh api repos/{owner}/{repo}/issues/comments/<id> --jq .body`. Compare the body with the file's text, ignoring line endings, trailing white space and anything the session's tooling appended below it, such as a footer after a `---` line. When it differs, write the file's text over it once, from the same file, with `gh api -X PATCH repos/{owner}/{repo}/pulls/comments/<id> -F body=@<file>` or `gh api -X PATCH repos/{owner}/{repo}/issues/comments/<id> -F body=@<file>`, and read it back again; when it still differs, stop and name its URL. A `/review` comment is the one exception: post it as the review request says and leave it as it was posted.
