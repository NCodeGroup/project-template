Then, when the project runs NCode Review, as NCode Review Findings says, and the host is GitHub, ask it to review the commits just pushed. A push alone starts no review: `.github/workflows/code-review.yml` reviews a pull request when it opens or is marked ready, and again only on a new top-level comment from someone who can write to the repository whose first line is `/review`. NCode Review reads the command from that first line and sets aside everything from a `---` line on, so a footer the session's tooling appends below it, such as a Claude Code cloud session's or another agent's attribution, doesn't stop the review. Write a file whose only line is `/review` and post it as a top-level comment on the pull request with `gh pr comment <number> --body-file <file>`. Leave that comment as it was posted, with whatever the session's tooling appended: never read it back, edit or delete it. The `/review` comment is the one the run writes that doesn't start with `Autopilot:`; it is only a slash command, so no check answers it.
