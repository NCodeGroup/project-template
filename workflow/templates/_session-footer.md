On GitHub, a session's own GitHub tooling can add agent attribution to what it posts: a Claude Code cloud session appends a line `---` and then a footer line `_Generated by [Claude Code](https://claude.ai/code/…)_` to each pull request description, issue, comment and review-thread reply it creates, through `gh` and the GitHub MCP tools alike, while `gh` in a local session appends nothing. So straight after each command that creates or edits a pull request description, an issue or a top-level comment, read back what was saved: `gh pr view <number> --json body --jq .body` for a pull request, `gh issue view <number> --json body --jq .body` for an issue, or `gh api "repos/{owner}/{repo}/issues/comments/<id>" --jq .body` for a comment, where `<id>` is the number after `#issuecomment-` in the URL the command printed. When the last line of it that isn't blank starts with `Generated with [Claude Code` or `Generated by [Claude Code`, after any symbols or underscores, or holds only a `claude.ai/code/session_` link, remove that line, the `---` line above it, when there is one, and the blank lines between and after them, and keep every other line as it was. Remove it with the GitHub MCP tools, which don't append the footer again: `update_pull_request` with the new body for a pull request, `issue_write` with `method: update` and the new body for an issue, or `update_issue_comment` with the comment's id and the new body for a comment. Never remove it through `gh`: in such a session `gh api -X PATCH` appends the footer again. Then read it back once more, and when the footer is still there, or the GitHub MCP tools aren't available, leave it and list it in your report. A reply on a review thread is the one exception: nothing the session can call edits one without the footer, so post each reply as these instructions say anyway, because every finding still gets its reply, and list the replies in your report as ones that may carry the footer.
