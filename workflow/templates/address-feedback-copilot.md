## Checkout

The run works in a worktree of its own, `.claude/worktrees/feedback-<number>`, on the branch `worktree-feedback-<number>`, made from the pull request's branch, with `PLAN.md` untracked at its root, and `<worktree path>` is its absolute path. Start every command for the run with `Set-Location -LiteralPath '<worktree path>';`, and give file tools and every subagent that folder. `orchestrate-plan` hands each step to the executor it names for this tool: in Copilot Chat the Copilot Implementer, or the Local Implementer when the repository has only the Hybrid agents; in Copilot CLI the `plan-executor` agent. An earlier run on a pull request is still open, for Start item 3, when the folder `.claude/worktrees/feedback-<number>` exists, which `/continue-plan feedback-<number>` shows, or when the branch `feedback-<number>` exists, which an earlier Copilot version left and item 5 moves into that worktree.

1. Start item 1: run `git rev-parse --show-toplevel`. When the path contains `/.claude/worktrees/`, stop and say to run this command in a new session in the main checkout. The main checkout is never switched, and its working tree may hold other work. When `git branch --show-current` prints `feedback-<n>`, where `<n>` is digits: when `<n>` is the number of the pull request the request names, the main checkout holds that pull request's open run, which Resume finishes, and item 5 moves it; otherwise stop, because another pull request's run is open here, and `/address-feedback <n>` finishes it. In the run summary Start item 6 shows, also say that the run must not stop for approvals: in Copilot Chat, choose the Bypass Approvals or Autopilot permission level; in Copilot CLI, run `/allow-all`, or start the session with `copilot --allow-all`. With those, `git push` runs without an approval prompt too, so after my yes to that summary, no prompt stops the run's pushes.
2. Plan item 1: create the worktree from the main checkout. When `git check-ignore -q .claude/worktrees/` exits non-zero, append the line `.claude/worktrees/` to `info/exclude` in the folder that `git rev-parse --path-format=absolute --git-common-dir` prints. Run `git fetch origin "refs/heads/<head>"`, then `git worktree add --no-track .claude/worktrees/feedback-<number> -b worktree-feedback-<number> "origin/<head>"`.
3. Reply's end: when `git -C '<worktree path>' status --porcelain` prints nothing and its `HEAD` equals `origin/<head>`, delete `<worktree path>/PLAN.md`, then run `git worktree remove '<worktree path>'` and `git branch -D worktree-feedback-<number>` from the main checkout: its commits are on the pull request's branch. Otherwise leave the worktree as it is.
4. Stop: when the run never made `<worktree path>`, there is nothing to remove. When the run stopped before its `PLAN.md` was written, and `git -C '<worktree path>' status --porcelain` prints nothing, run `git worktree remove '<worktree path>'` and `git branch -D worktree-feedback-<number>` from the main checkout. Otherwise leave the worktree, with its commits and `PLAN.md`: `/continue-plan feedback-<number>` shows it, and `/address-feedback <number>` in a new session in the main checkout finishes it.
5. Resume: when the folder `.claude/worktrees/feedback-<number>` exists, the run resumes there; `<worktree path>` is its absolute path. Otherwise only the branch `feedback-<number>` exists, where a run of an earlier Copilot version stopped: move that run into the worktree, which changes none of its commits and no line of its `PLAN.md`. `<folder>` is the path on the `worktree` line of the entry in `git worktree list --porcelain` whose `branch` line is `branch refs/heads/feedback-<number>`, and the run's `PLAN.md` is at its root. When no entry has that line, stop and say to switch to the branch with its `PLAN.md`, `git switch feedback-<number>`, in the folder that holds that `PLAN.md`, and to run this command again. Stop, and say why, when the branch `worktree-feedback-<number>` exists too, when `git -C <folder> status --porcelain` prints anything, which you list, or when `<folder>` holds a `PLAN.md` and running `{{STATE_SCRIPT}}` with `-NoFetch -Path <folder>` added prints a `feedback` other than `<number>`, because that plan isn't this run's. Run `git -C <folder> switch "<default>"`, which carries `PLAN.md` along and leaves `<folder>` on the default branch, as a Copilot run's end does; when it fails, such as when `<default>` is checked out in another folder, stop with Git's message: nothing has moved yet. Then, from the main checkout, make sure `.claude/worktrees/` is ignored, as item 2 says, and run `git branch -m feedback-<number> worktree-feedback-<number>` and `git worktree add .claude/worktrees/feedback-<number> worktree-feedback-<number>`. Move `<folder>/PLAN.md`, when it exists, to the new worktree's root; `<worktree path>` is the new worktree's absolute path. When one of these steps fails, stop with Git's message, and say that the run's commits are on its branch and its `PLAN.md` is in `<folder>` or the worktree.
6. Discard: delete `<worktree path>/PLAN.md`, then run `git worktree remove --force <worktree path>` and `git branch -D worktree-feedback-<number>` from the main checkout.
