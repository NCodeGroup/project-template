## Checkout

The run works in this folder, on a branch of its own, `feedback-<number>`, made from the pull request's branch, with `PLAN.md` at the repository root, untracked, as every Copilot plan is. Switch branches only where this section says to: `PLAN.md` is untracked, so a switch carries it along, and it belongs to `feedback-<number>`. `orchestrate-plan` hands each step to the executor it names for this tool: in Copilot Chat the Copilot Implementer, or the Local Implementer when the repository has only the Hybrid agents; in Copilot CLI the `plan-executor` agent. An earlier run on a pull request is still open, for Start item 3, when the branch `feedback-<number>` exists, which `git rev-parse --verify --quiet refs/heads/feedback-<number>` shows by printing a commit and `/continue-plan` shows once it is checked out, or when the folder `.claude/worktrees/feedback-<number>` exists, which a Claude Code run leaves and item 5 moves into this folder.

1. Start item 1: run `git rev-parse --show-toplevel`. When the path contains `/.claude/worktrees/`, stop and say to run this command in the main checkout. When `git branch --show-current` prints `feedback-<n>`, where `<n>` is digits: when `<n>` is the number of the pull request the request names, the folder holds that pull request's open run, which Resume finishes here, so skip this item's `PLAN.md`, working tree and `<return>` checks; otherwise stop, because another pull request's run is open here, and `/address-feedback <n>` finishes it. When `PLAN.md` exists at the repository root, stop: a plan is in progress here, and `/continue-plan` shows where it stands. When `git status --porcelain` prints anything, stop and list it, because the run switches branches. Note `<return>`, the branch `git branch --show-current` prints, which the run switches back to at its end; stop and say to check out a branch when it prints nothing, or a name that fails Start item 3's check for `<head>`. In the run summary Start item 6 shows, also say that the run must not stop for approvals: in Copilot Chat, choose the Bypass Approvals or Autopilot permission level; in Copilot CLI, run `/allow-all`, or start the session with `copilot --allow-all`. With those, `git push` runs without an approval prompt too, so after my yes to that summary, no prompt stops the run's pushes.
2. Plan item 1: run `git fetch origin "refs/heads/<head>"`, then `git switch --no-track -c feedback-<number> "origin/<head>"`.
3. Reply's end: when `git status --porcelain` prints nothing and `git rev-parse HEAD` equals `git rev-parse "origin/<head>"`, delete `PLAN.md` when it exists, then run `git switch "<return>"` and `git branch -D feedback-<number>`: its commits are on the pull request's branch. Otherwise leave `feedback-<number>` checked out as it is.

Otherwise leave the branch checked out as it is, with its commits and `PLAN.md`: `/continue-plan` shows it, and `/address-feedback <number>` in a new session in this folder finishes it.
5. Resume: when `feedback-<number>` is checked out, the run resumes in this folder, and `<return>` is `<default>`. When the branch exists while another branch is checked out, stop and say to switch to it with its `PLAN.md`, `git switch feedback-<number>`, and to run this command again. Stop, and say why, when there is no such line, when that entry's `branch` line isn't `branch refs/heads/worktree-feedback-<number>`, when `git -C <worktree path> status --porcelain` prints anything, which you list, or when `<worktree path>` holds a `PLAN.md` and running `{{STATE_SCRIPT}}` with `-NoFetch -Path <worktree path>` added prints a `feedback` other than `<number>`, because that plan isn't this run's.
