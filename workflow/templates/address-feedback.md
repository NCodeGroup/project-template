## Checkout

The run works in a worktree of its own, `.claude/worktrees/feedback-<number>`, on the branch `worktree-feedback-<number>`, and `<worktree path>` is its absolute path. A planning stage, such as `plan-bugfix`, runs with `model: opus`, `review-plan-diff` with `model: sonnet`, and `orchestrate-plan` hands each step to the `plan-executor` subagent. Tell each subagent that the plan's folder is `<worktree path>` and never to call `EnterWorktree`: `plan-bugfix`'s `## Plan in a worktree of its own` section and `review-plan-diff`'s `## Work in the plan's worktree` section are done, so `plan-bugfix` skips that section's steps 1 to 3 and makes no `Plan:` commit. An earlier run on a pull request is still open, for Start item 3, when the folder `.claude/worktrees/feedback-<number>` exists, which `/continue-plan feedback-<number>` shows, or when the branch `feedback-<number>` exists, which a Copilot run leaves and item 5 moves into that worktree.

1. Start item 1: run `git rev-parse --show-toplevel`. When the path contains `/.claude/worktrees/`, the session is in a worktree, such as a plan's after `/ship-plan`: leave it with the `ExitWorktree` tool and `action: "keep"`, which keeps the worktree, its branch and its `PLAN.md` as they are, then run `git rev-parse --show-toplevel` again. When that path no longer contains `/.claude/worktrees/`, say that you left the worktree `<the first path>` and kept it, and go on from the main checkout. When it still does, the session can't leave the worktree: it didn't enter it with the `EnterWorktree` tool, such as a session started with `claude --worktree <name>`, so `ExitWorktree` changed nothing, or the tool isn't there. Then stop and say to run this command in a new session in the main checkout.
2. Plan item 1: create the worktree from the main checkout. When `git check-ignore -q .claude/worktrees/` exits non-zero, append the line `.claude/worktrees/` to `info/exclude` in the folder that `git rev-parse --path-format=absolute --git-common-dir` prints. Run `git fetch origin "refs/heads/<head>"`, then `git worktree add --no-track .claude/worktrees/feedback-<number> -b worktree-feedback-<number> "origin/<head>"`, and switch into the new worktree with the `EnterWorktree` tool and its `path`.
3. Reply's end: when `git status --porcelain` prints nothing in the worktree and `git rev-parse HEAD` equals `git rev-parse "origin/<head>"`, return to the main checkout with the `ExitWorktree` tool and `action: "keep"`, then run `git worktree remove <worktree path>` and `git branch -D worktree-feedback-<number>`: its commits are on the pull request's branch. Otherwise leave the worktree as it is.
4. Stop: when the run never made or entered `<worktree path>`, there is nothing to leave. Otherwise return to the main checkout with the `ExitWorktree` tool and `action: "keep"`. When the run stopped before its `PLAN.md` was written, and `git -C <worktree path> status --porcelain` prints nothing, remove the worktree as item 3 says. Otherwise leave it, with its commits and `PLAN.md`: `/continue-plan feedback-<number>` shows it, and `/address-feedback <number>` in a new session in the main checkout finishes it.
5. Resume: when the folder `.claude/worktrees/feedback-<number>` exists, switch into it with the `EnterWorktree` tool and its `path`; `<worktree path>` is its absolute path. Otherwise only the branch `feedback-<number>` exists, where a Copilot run stopped: move that run into the worktree, which changes none of its commits and no line of its `PLAN.md`. `<folder>` is the path on the `worktree` line of the entry in `git worktree list --porcelain` whose `branch` line is `branch refs/heads/feedback-<number>`, and the run's `PLAN.md` is at its root. When no entry has that line, stop and say to switch to the branch with its `PLAN.md`, `git switch feedback-<number>`, in the folder that holds that `PLAN.md`, and to run this command again. Stop, and say why, when the branch `worktree-feedback-<number>` exists too, when `git -C <folder> status --porcelain` prints anything, which you list, or when `<folder>` holds a `PLAN.md` and running `{{STATE_SCRIPT}}` with `-NoFetch -Path <folder>` added prints a `feedback` other than `<number>`, because that plan isn't this run's. Run `git -C <folder> switch "<default>"`, which carries `PLAN.md` along and leaves `<folder>` on the default branch, as a Copilot run's end does; when it fails, such as when `<default>` is checked out in another folder, stop with Git's message: nothing has moved yet. Then, from the main checkout, make sure `.claude/worktrees/` is ignored, as item 2 says, and run `git branch -m feedback-<number> worktree-feedback-<number>` and `git worktree add .claude/worktrees/feedback-<number> worktree-feedback-<number>`. Move `<folder>/PLAN.md`, when it exists, to the new worktree's root, then switch into the worktree with the `EnterWorktree` tool and its `path`; `<worktree path>` is its absolute path. When one of these steps fails, stop with Git's message, and say that the run's commits are on its branch and its `PLAN.md` is in `<folder>` or the worktree.
6. Discard: return to the main checkout with the `ExitWorktree` tool and `action: "keep"`, then run `git worktree remove --force <worktree path>` and `git branch -D worktree-feedback-<number>`.
